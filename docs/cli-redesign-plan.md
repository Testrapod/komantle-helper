# 토끼 마스코트 중심 CLI 개편 계획

작성일: 2026-10-25 · 상태: 구현 반영

사용자 후속 결정: 하위 호환 유지보다 구조 정리를 우선한다. 숫자 메뉴·별도 게임 루프·`--play`와
기존 `main.py` 모델 API를 제거하고 수집기와 테스트도 새 패키지를 직접 사용한다.
현재 명령과 실제 모듈 구조는 [CLI 사용 안내](cli.md)를 기준으로 한다.
아래 내용은 최초 설계의 목적과 검토 기준을 기록한다.

## 1. 목표와 방향

기존 토끼를 프로그램의 안내자로 삼고, 하나의 입력창에서 추측과 슬래시 명령을 함께 사용하는 터미널 앱으로 개편한다. 시작 직후 플레이할 수 있고, `/`만 입력해도 기능을 발견할 수 있어야 한다.

Claude Code·Codex CLI에서 기대하는 명령 탐색, 입력 편집, 상태 표시, 이어지는 작업 흐름을 이 게임에 맞게 적용한다. 입력 문법은 명확하게 유지하며, 자연어 해석이나 AI 호출은 추가하지 않는다.

제품 원칙:

- **바로 시작**: 오늘 회차를 기본으로 준비하고 기존 기록이 있으면 이어간다. 최초 예/아니오 메뉴를 없앤다.
- **하나의 작업 공간**: 게임과 힌트 사이에 메뉴 이동이 없다. 힌트 대상 순위와 게임 회차를 구분한다.
- **필요한 만큼 공개**: 자동완성과 안내 문구가 숨겨진 단어를 노출하지 않는다.
- **귀엽고 차분하게**: 토끼의 정체성은 살리고 입력과 결과를 가장 읽기 쉽게 만든다.
- **웹과 기능 동등성**: 웹의 여섯 힌트, 게임, 회차 선택, 기록 관리와 데이터 상태를 모두 제공한다.

## 2. 현재 코드에서 확인한 사항

| 영역 | 현재 구현 | 개편 시 처리 |
| --- | --- | --- |
| 시작 토끼 | `main.py::_run()`의 세 줄 토끼와 영문 말풍선 | 토끼 형태 보존, 시작 화면·작업 상태로 확장 |
| 힌트 CLI | 숫자 1~5, 순위를 매번 질문하는 반복 메뉴 | 슬래시 명령과 지속되는 대상 순위로 교체 |
| 한 글자 | `기존 회차 조회 객체.get_one_character()` 존재, CLI 메뉴에 없음 | `/hint char <위치>`로 노출 |
| 게임 CLI | `game.py::run_game()`, `/기록`, `/포기`, `/돌아가기` | 같은 입력창으로 통합, 기록·채점 로직 활용 |
| 회차 데이터 | CLI는 원본 `top_scores` 직접 조회 | 웹과 같은 공개 아카이브 및 로컬 캐시 추가 |
| 웹 힌트 | 여섯 힌트 개별 공개/숨기기, 전체 단어 확인창 | 힌트 패널과 공개 확인 흐름으로 대응 |
| 웹 게임 | 추측·정답·포기·중복 방지·이어하기·기록 삭제 | CLI의 누락 기능 추가, 기존 게임 규칙 유지 |
| 품사 | CLI는 필요할 때 Okt/Java 시작, 웹은 저장된 품사 사용 | 아카이브 품사 우선, 원본 조회 경로만 필요 시 분석 |
| 저장 | CLI JSON 파일과 웹 localStorage가 별도 | 기존 CLI 저장 경로·형식 유지, 웹과 자동 동기화하지 않음 |
| 결합도 | 수집기·스크립트·테스트가 `main.py`의 모델과 날짜 함수를 import | 화면과 공통 로직 분리, 수집기·테스트 import를 새 모듈로 변경 |

웹은 현재 Python CLI를 실행하는 구조가 아니다. Python이 수집한 JSON을 JavaScript가 읽고, 웹 게임은 별도 채점 API를 호출한다. 이번 개편에서는 데이터 계약과 동작 규칙을 맞추며, Python과 JavaScript 전체를 하나의 구현으로 합치는 재작성은 범위에 넣지 않는다.

## 3. 화면과 토끼 디자인

### 시작 화면

아래는 레이아웃 예시이며 회차·단어·점수는 실제 데이터 표시를 뜻하지 않는다.

```text
 (\_/)     꼬맨틀 헬퍼
 ( •‿•)    오늘의 단어로 가는 작은 실마리
 / > <\

 1667회 · 2026-10-24 · 이어하기: 7번 추측
 단어를 입력해 추측하거나 / 로 명령을 찾아보세요.

 › _
 ──────────────────────────────────────────────
 1667회 · 힌트 대상: 정답 · 추측 7회 · 저장됨
 / 명령   ↑↓ 입력 기록   Ctrl+D 종료
```

환영 화면은 한 번만 출력한다. 이후 명령마다 큰 토끼와 메뉴를 다시 출력하지 않는다. 오늘 데이터가 없어서 이전 회차로 시작했다면 시작 문구와 상태 줄에 해당 사실을 명시한다.

### 플레이 화면

```text
 › 과일
   8번째 추측 · 과일 · 유사도 51.25 · 1위
   지금까지 가장 가까운 단어예요.

 [힌트 · 1667회 · 정답]
   길이  2글자       품사  숨김       초성  ㅅㄱ
   유사도  숨김      한 글자  숨김    전체 단어  숨김

 › /hint _
   length       단어 길이
   pos          품사
   initial      초성
   similarity   정답과의 유사도
   char         지정한 위치의 한 글자
   word         전체 단어 공개 · 확인 필요

 1667회 · 힌트 대상: 정답 · 추측 8회 · 저장됨
```

화면은 위쪽의 실행 기록과 아래쪽의 갱신 영역으로 구성한다. 갱신 영역에는 힌트 패널, 입력창, 자동완성/확인 선택지, 상태 줄이 들어간다. 보통 터미널의 스크롤 기록을 유지하는 인라인 UI로 시작한다.

긴 `/history` 결과는 실행 기록에 표로 출력하고, 기본 화면은 마지막 추측과 요약을 보여준다. 긴 목록은 한 번에 전부 출력하지 않고 페이지 단위로 확인한다. 좁은 창에서는 힌트와 상태를 세로로 접는다.

### 토끼 사용 규칙

- 원형인 `(\_/)`, `( •‿•)`, `/ > <\`를 기준으로 한다. 별도 이미지나 이모지 폰트에 의존하지 않는다.
- 시작·첫 힌트·정답·종료 같은 중요한 순간에 등장한다. 일상 결과는 짧은 문장으로 표시한다.
- 준비/조회 중/정답/연결 오류 상태에 작은 표정 변화를 줄 수 있다. 오류에서는 원인과 복구 명령이 먼저 보인다.
- 반복 점프나 타이핑 중 애니메이션은 기본값에서 제외한다. 로딩 표시는 작게, 장식 효과는 설정으로 끌 수 있게 한다.
- 기존 얼굴의 `•`, `‿`는 유니코드 문자다. 엄격한 ASCII 옵션에서는 `(o.o)` 같은 대체 얼굴을 제공한다.

### 색과 가독성

- 기본 배경은 터미널 설정을 따른다. 밝은 테마와 어두운 테마 모두 검증한다.
- 브랜드 강조는 차분한 당근색, 성공은 초록색, 주의는 노란색으로 제한한다.
- 색 외에도 `저장됨`, `저장 실패`, `조회 중` 같은 텍스트 상태를 반드시 제공한다.
- 강한 박스와 구분선을 남발하지 않는다. 단어·점수·현재 대상의 위계를 여백과 굵기로 표현한다.
- 100열 이상은 여유 있는 배치, 80열은 기본 배치, 40~79열은 세로 배치로 대응한다. 40열 미만은 최소 텍스트 화면으로 전환한다. 낮은 높이에서는 자동완성 항목 수부터 줄인다.
- 한글의 화면 폭과 커서 위치, 터미널 리사이즈를 실제 터미널에서 검증한다.

## 4. 입력과 명령 체계

영문 명령을 정식 문법으로 두고 한글 별칭을 동일한 명령에 연결한다. 도움말과 자동완성은 한국어 설명을 제공한다. 숫자는 회차·순위·글자 위치의 인자로만 사용하며, 메뉴 선택용 숫자·알파벳 입력은 없앤다.

| 명령 | 동작 | 한글 별칭 예 |
| --- | --- | --- |
| 일반 단어 입력 | 현재 게임 회차에 추측 제출 | 동일 |
| `/help` | 명령과 사용 예시 | `/도움말` |
| `/round` | 날짜·회차·저장 상태가 있는 검색 가능한 회차 선택기 | `/회차` |
| `/round today`, `/round latest`, `/round 1667` | 오늘/최신 보관 회차/지정 회차 선택 | `/회차 오늘`, `/회차 최신`, `/회차 1667` |
| `/rank` 또는 `/rank 50` | 현재 힌트 대상 선택/50위로 변경, 0은 정답 | `/순위 50` |
| `/hint` | 힌트 종류 선택기 | `/힌트` |
| `/hint length` | 길이 공개 | `/힌트 길이` |
| `/hint pos` | 품사 공개 | `/힌트 품사` |
| `/hint initial` | 초성 공개 | `/힌트 초성` |
| `/hint similarity` | 유사도 공개 | `/힌트 유사도` |
| `/hint char 2` | 두 번째 글자 공개, 사용자 위치는 1부터 시작 | `/힌트 글자 2` |
| `/hint word` | 확인 후 선택한 순위의 전체 단어 공개 | `/힌트 단어` |
| `/hide` 또는 `/hide all` | 현재 힌트 모두 숨기기 | `/숨기기` |
| `/hide initial` | 특정 힌트만 숨기기 | `/숨기기 초성` |
| `/history` | 추측 기록을 유사도 내림차순으로 표시 | `/기록` |
| `/history --sort recent` | 최근 입력 순으로 표시 | `/기록 --sort recent` |
| `/history --page 2` | 긴 기록의 다음 페이지 표시 | `/기록 --page 2` |
| `/giveup` | 확인 후 정답 공개와 포기 저장 | `/포기` |
| `/records delete current` | 확인 후 현재 회차 기록 삭제·새 게임 | `/기록삭제 현재` |
| `/records delete all` | 확인 후 전체 CLI 회차 기록 삭제·현재 회차 새 게임 | `/기록삭제 전체` |
| `/status` | 회차·날짜·출처·수집 시각·채점 제약·저장 경로 | `/상태` |
| `/links` | 원본 게임과 GitHub 링크 표시 | `/링크` |
| `/refresh` | 데이터 목록과 현재 회차를 다시 조회 | `/새로고침` |
| `/settings` | 색·장식 효과 등 화면 설정 | `/설정` |
| `/clear` | 화면 정리, 게임 기록은 유지 | `/화면정리` |
| `/quit` | 저장 상태를 안내하고 종료 | `/종료` |

인자가 없는 `/records`와 `/records delete`는 범위 선택기를 연다. `/history`는 기본 20개씩 표시하고 다음 페이지 명령을 안내한다. `/round` 목록은 위아래 키로 탐색하며 날짜·회차로 검색한다. `/rank` 선택기에는 순위만 표시하고 해당 단어는 표시하지 않는다. 명령 정의 한 곳에서 파싱, 별칭, 도움말, 자동완성, 인자 검증을 생성해 서로 어긋나지 않게 한다.

### 키보드 규칙

- `/` 입력: 설명이 붙은 명령 팔레트. 이어서 입력하면 명령/별칭을 필터링한다.
- `Tab`: 명령 또는 인자 완성. 자동완성은 명령·힌트 종류·회차 메타데이터만 사용한다.
- `↑↓`: 팔레트가 열려 있으면 항목 이동, 닫혀 있으면 현재 실행의 입력 기록 탐색.
- `Enter`: 일반 입력은 제출. 자동완성 항목 선택은 먼저 입력을 완성하며, 특히 공개·삭제 명령은 추가 확인 전 실행하지 않는다.
- `Esc`: 팔레트·확인 선택지 취소. 입력창에서는 작성 중인 내용 유지.
- `Ctrl+C`: 입력/진행 중 작업 취소 후 프롬프트로 복귀. 명령 취소를 프로그램 종료로 취급하지 않는다.
- `Ctrl+D`: 빈 입력창에서 종료. 내용이 있으면 일반 편집 동작을 따른다.
- 알 수 없는 `/hstory`는 `/history` 후보와 예시를 보여준다. 추측 API로 보내지 않는다.
- 여러 줄 붙여넣기는 자동 제출하지 않는다. 입력창에서 오류와 수정 방법을 안내하고 명시적인 제출을 기다린다.

확인 UI는 `[취소] [공개하기]` 같은 방향키 선택 방식이며 기본 포커스는 취소다. `y/N`이나 번호를 외우게 하지 않는다. 한글 IME 조합, 붙여넣기, 백스페이스도 수동 검증 항목에 포함한다.

## 5. 기능별 상태와 UX 계약

### 회차와 힌트 대상

- 앱 상태는 `현재 게임 회차`와 `힌트 대상 순위`를 별도로 가진다. `/rank 50`을 실행해도 추측은 해당 회차의 정답을 대상으로 한다.
- 회차를 바꾸면 힌트 대상은 0으로 돌아가고 공개 힌트·한 글자 위치·확인 UI를 초기화한다. 새 회차의 게임 기록을 복원한다.
- 순위를 바꾸면 공개 힌트와 글자 위치를 초기화하고 게임 기록은 유지한다. 같은 순위를 다시 선택해도 웹과 같이 초기화한다.
- 글자 위치를 바꾸면 이전 글자 공개를 닫고 새 위치의 글자만 공개한다. 유효 범위를 넘으면 값과 기존 공개 상태를 변경하지 않는다.
- 한국 날짜가 바뀌면 상태 줄에 새 회차 알림을 표시한다. 플레이 중인 회차를 자동으로 바꾸지 않고 `/round today`로 이동하게 한다.

### 공개와 숨기기

- `/hint`는 이미 공개된 종류를 다시 실행해도 공개 상태를 유지한다. 숨기기는 `/hide`로 명확하게 분리한다.
- 힌트 값은 갱신 영역에만 표시한다. 실행 기록에는 `초성을 공개했어요`처럼 값을 포함하지 않는 결과만 남긴다.
- `/hint word`는 정답 순위뿐 아니라 모든 순위에서 공개 대상을 표시하고 확인한다. 힌트로 전체 단어를 보는 행위는 게임 포기 상태를 저장하지 않는다. `/giveup`과 구분한다.
- `/hide`, 회차/순위 변경, 종료 시 갱신 영역의 공개 값을 제거한다. 공개 상태는 디스크에 저장하지 않고 다시 시작하면 모두 숨긴다.
- 터미널 녹화나 이미 생긴 스크롤백까지 완전히 지우는 것은 보장할 수 없다. 첫 단계에서 힌트의 노출·숨김·리사이즈·종료를 실제 터미널로 검증한다. 인라인 갱신만으로 기준을 만족하지 못하면 힌트 상세 표시를 임시 대체 화면으로 전환한다.
- 일반 텍스트 모드에서는 출력한 힌트를 되돌려 숨길 수 없다는 점을 해당 명령에서 짧게 알린다.

### 게임과 기록

- 기존 단어 정규화, 유사도 -100~100 단위, 회차당 1,000번 제한, 중복·실패 시 횟수 미증가 규칙을 유지한다.
- 기본 기록 정렬은 웹처럼 유사도 내림차순, 동점은 최근 시도 우선이다. 마지막 입력은 별도 표시한다.
- 가장 좋은 추측과 마지막 추측을 구분한다. 점수 변화로 의미론적 조언을 만들어내지 않는다.
- 정답이면 토끼의 짧은 축하, 시도 횟수, 다음 행동을 보여준다. 종료된 회차도 힌트와 기록 조회는 가능하다.
- 포기 여부와 정답 상태를 복원한다. 다시 플레이하려면 현재 회차 기록 삭제를 명시적으로 선택한다.
- `~/.local/state/komantle-helper/game-<회차>.json`, `--state-dir`, `KOMANTLE_STATE_DIR`와 기존 JSON 형식을 유지한다.
- 기록 읽기 실패와 저장 실패를 구분해 경고한다. 쓰기 실패여도 메모리에서는 플레이를 계속할 수 있고 `저장 실패` 상태가 남는다.
- 삭제 확인에는 대상 회차/전체 범위와 삭제되는 기록 수를 표시한다. 전체 삭제도 이 앱의 `game-<회차>.json` 파일만 대상으로 한다. 설정·데이터 캐시는 삭제하지 않는다.
- 삭제 실패 시 성공으로 표시하지 않는다. 일부만 삭제되면 실제 삭제/실패 범위를 보여주고 현재 회차를 디스크 상태에 맞춰 다시 연다. 이전 비동기 결과가 삭제된 기록을 되살리지 못하도록 작업을 무효화한다.
- 입력 편집 기록은 우선 메모리에서만 유지한다. 정답·공개 힌트를 별도 입력 기록 파일에 중복 저장하지 않는다.

### 로딩과 오류

- 데이터 준비 중에도 화면을 즉시 띄우고 `/help`, `/status`, `/quit`를 사용할 수 있게 한다.
- 조회/채점 동안 짧은 상태 표시를 제공한다. 중복 제출을 막고 입력 내용은 실패 시 유지한다.
- 연결 실패·사전에 없는 단어·채점 기간 종료·요청 제한·데이터 손상을 서로 다른 문장과 다음 행동으로 안내한다.
- 과거 회차는 보관된 단어를 계속 채점할 수 있다. 원본 API가 거부한 미보관 단어는 사유를 보여주고 시도 횟수를 늘리지 않는다. 서버의 조회 가능 기간을 고정된 일수로 가정하지 않는다.
- 회차를 옮기거나 취소한 요청의 늦은 응답이 화면과 저장 기록에 반영되지 않도록 한다.

## 6. 데이터와 실행 구조

### 데이터 획득 정책

1. 검증된 로컬 캐시가 있으면 먼저 표시하고 공개 manifest 갱신을 시도한다.
2. 웹과 같은 배포 아카이브에서 manifest와 선택 회차 JSON을 읽는다. 기본 URL은 `https://testrapod.github.io/komantle-helper/data/manifest.json`으로 두고 실제 배포 경로를 구현 때 확인한다.
3. 스키마·회차/날짜·1,001개 순위·유사도 단위·파일 해시를 검증하고 원자적으로 캐시한다. 기존 보관 데이터의 점수 단위 변환 규칙도 유지한다.
4. 기본 시작은 오늘 보관 회차다. 없으면 최신 보관 회차를 열되 `오늘 데이터 갱신 대기 · 현재 …회`를 분명히 표시한다. `/round today`처럼 명시적으로 요청한 회차가 없으면 임의의 다른 회차로 바꾸지 않는다.
5. 아카이브에 없는 회차는 원본 직접 조회로 보완한다. 오늘 회차의 갱신 대기 시 직접 조회 선택지도 제공한다. 이때 수집 시각과 데이터 출처를 실제 값으로 표시한다.
6. 원본 경로의 품사는 요청 시에만 Okt를 사용한다. 분석기를 사용할 수 없어도 다른 힌트·게임은 계속된다. 아카이브의 저장된 품사는 Java 없이 제공한다.
7. 게임 채점은 보관 데이터 우선, 미보관 단어는 기존 `score_upstream()`의 직접 API 경로를 유지한다. 웹의 중계 API를 CLI 필수 의존성으로 추가하지 않는다.

네트워크와 캐시가 모두 없으면 조회 불가 상태로 앱을 유지한다. 캐시가 있으면 오프라인 힌트와 보관 단어 채점을 제공한다. `/refresh` 실패가 기존 정상 데이터와 게임 기록을 지우지 않게 한다. 같은 회차를 새로 읽더라도 추측 기록을 보존하고, 데이터가 바뀐 경우 힌트 공개 상태는 닫는다.

캐시는 `~/.cache/komantle-helper/`를 기본으로 하며 `XDG_CACHE_HOME`을 존중한다. 기존 게임 기록 경로는 별도로 유지한다. 캐시는 회차 사용 시 필요한 파일만 읽고, 회차를 바꿀 때마다 전체 아카이브를 검증하는 방식은 피한다.

### 권장 기술

Python 기반을 유지하고 `prompt_toolkit`으로 입력·팔레트·갱신 영역·키 처리를, `Rich`로 기록 표와 정적 결과 출력을 구현한다. `prompt_toolkit`은 자동완성·상태 툴바와 비동기 앱 실행을 지원하고, Rich는 표 출력과 터미널/색상 감지를 제공한다. [입력 문서](https://python-prompt-toolkit.readthedocs.io/en/stable/pages/asking_for_input.html), [비동기 실행 문서](https://python-prompt-toolkit.readthedocs.io/en/stable/pages/advanced_topics/asyncio.html), [Rich Console 문서](https://rich.readthedocs.io/en/stable/console.html).

동적인 화면의 소유자는 `prompt_toolkit` 하나로 한정한다. Rich의 별도 Live 루프를 동시에 돌리지 않고, 정적 출력은 입력 렌더링을 안전하게 중단하는 경로로 처리한다. 라이브러리 버전은 첫 프로토타입에서 Python 3.12 및 기존 의존성과 함께 검증한 뒤 고정한다.

### 구현한 모듈 경계

```text
main.py                         저장소 실행 진입점
komantle_helper/
  core.py                       Word, RoundData, 날짜·초성·지연 분석
  archive.py                    공유 아카이브 검증·원자적 I/O
  data.py                       원본 API·공개 아카이브·캐시
  game.py                       게임 규칙·채점·저장·범위 삭제
  cli/
    app.py                      상태·입력·키·선택·작업 생명주기
    commands.py                 명령 명세·별칭·파싱·완성
    views.py                    토끼·힌트·기록·스타일
    workers.py                  동기 I/O·취소·빠른 종료
```

데이터/게임 로직은 `print()`나 `input()`을 호출하지 않는다. 수집기·빌드 스크립트와 테스트는
공통 패키지를 직접 참조한다. 이전 모델 API를 위한 재노출 계층은 만들지 않는다.

비동기 처리는 기존 requests 호출을 작업 스레드로 분리하는 것부터 시작한다. 취소는 작업 ID/회차 ID로 결과를 무효화하고 네트워크 시간 제한을 유지한다. 취소된 스레드가 뒤늦게 반환해도 저장되지 않도록 **채점 결과 획득**과 **현재 세션에 반영·저장**을 분리한다. 게임 제출·삭제는 동시에 반영되지 않도록 직렬화한다.

## 7. 실행과 프로젝트 정리

- 설치 후 `komantle`, `python -m komantle_helper`, 저장소에서 `python main.py`로 동일한 앱을 실행한다.
- `--round`와 `--state-dir`는 통합 화면에 직접 적용한다. `--play`와 숫자/G/Q 메뉴는 제거한다.
- 기본 CLI 의존성과 선택 분석 모듈을 `pyproject.toml`에서 관리한다. 개발·수집 설치는 `requirements.txt`로 연결한다.
- `--plain`, `--no-color`, `--no-animation`, `--ascii`를 제공한다. `NO_COLOR`도 존중한다.
- 입출력이 TTY가 아니거나 `TERM=dumb`이면 plain 모드로 전환한다. 슬래시 명령 문법은 동일하다.
- plain 모드에서 공개·포기·삭제 확인이 필요하면 기본 취소하고 사유를 출력한다.
- 웹과 CLI 기록은 별도 저장임을 `/status`와 문서에 표시한다. 동기화는 이번 범위에 포함하지 않는다.

## 8. 개발 순서와 단계별 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1. 화면 프로토타입 | 합성 데이터로 토끼·입력창·팔레트·힌트 패널·확인 UI 구현 | 80/40열, 밝음/어두움, 한글 입력, 힌트 숨김과 스크롤백을 실제 터미널에서 확인 |
| 2. 공통 로직 분리 | 모델·날짜·분석·게임·저장 경계를 정리하고 호출부를 변경 | 기존 Python 테스트 통과, 수집/빌드 import 유지, 화면 없는 데이터 처리 가능 |
| 3. 아카이브/캐시 | manifest·단일 회차 검증, 아카이브 어댑터, 캐시·원본 보완 | 과거 회차 조회, 오프라인 캐시, 아카이브 품사의 Java 없는 사용, 손상 데이터 처리 |

각 단계는 개별 검토가 가능한 변경 단위로 진행한다. 1단계는 개발용 데모로 제공하고 새 기본 CLI 전환은 전체 기능이 연결된 뒤 수행한다. 기술 선택에서 가장 불확실한 한글 입력과 인라인 힌트 패널을 먼저 검증한다.

## 9. 검증 계획과 최종 완료 정의

### 웹 기능 동등성 시나리오

1. 오늘/최신/과거 회차 선택, 데이터 수집 시각·갱신 대기·실패·재시도 표시.
2. 0~1000위 선택, 길이·품사·초성·유사도·지정 위치 글자·전체 단어 공개.
3. 개별/전체 힌트 숨기기, 회차·순위·글자 위치 변경 시 공개 상태 정리.
4. 전체 단어 공개 확인 취소/승인, 힌트 공개와 포기의 상태 분리.
5. 보관 단어·원본 채점, 유사도 정렬, 최근 추측 표시, 정답·중복·실패 처리.
6. 포기 취소/승인과 재실행 이어하기, 종료된 게임의 조회.
7. 현재/전체 회차 기록 삭제 취소/승인, 범위 밖 파일 보존, 삭제 실패 안내.

### 자동 검증

- 명령 파싱·별칭·인자·자동완성 후보를 같은 명세에 대해 검증한다. 숨겨진 아카이브 단어가 후보에 섞이지 않음을 확인한다.
- 공개/숨김/회차 전환/포기/삭제/저장 실패의 상태 전이를 테스트한다.
- 네트워크 오류·오래된 manifest·파일 해시 불일치·구단위 데이터·오프라인 캐시를 고정 fixture로 검증한다.
- 가짜 입력 스트림과 PTY 통합 테스트로 팔레트·취소·EOF·확인 기본값·plain 모드를 검증한다.
- 회차 전환·요청 취소·기록 삭제 뒤 늦은 채점 응답이 저장되지 않는지 테스트한다.
- Python 전체 회귀 테스트, 웹 Node 단위 테스트 및 기존 Playwright 테스트를 실행해 공통 모델 변경의 영향을 확인한다.

### 실제 터미널 검증

우선 macOS Terminal과 iTerm2, 이후 VS Code 터미널에서 한글 입력/삭제/붙여넣기·리사이즈·스크롤·복사·종료 후 프롬프트 복구를 확인한다. 각 터미널은 사용 가능한 환경에서 실행하고, 미검증 환경을 완료로 표시하지 않는다. 40/80/120열, 낮은 높이, 밝은/어두운 테마, `NO_COLOR`, `TERM=dumb`, 파일 리다이렉션을 포함한다.

최종 완료 기준은 **사용자가 숫자 메뉴 없이 모든 웹 기능을 CLI에서 수행하고, 기존 기록을 이어서 쓰며, 토끼의 정체성이 있는 일관된 입력 경험을 얻는 것**이다. 구현된 동작과 실행 방법은 CLI 사용 안내와 README에서 관리한다.
