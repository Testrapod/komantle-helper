## GitHub Pages에서 제공할 수 있는가?

가능합니다. 권장 방식은 **GitHub Actions에서 Python으로 데이터를 만들고, GitHub Pages에서 웹 화면과 JSON을 제공**하는 구조입니다.
Python과 Java는 데이터 생성 시에만 실행하므로 방문자는 설치 없이 웹 브라우저로 사용할 수 있습니다.

[GitHub Pages는 HTML/CSS/JavaScript를 제공하는 정적 호스팅](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)입니다.
현재의 `input()` 기반 Python 프로그램과 Java 기반 Okt를 웹 서버처럼 실행하는 기능은 제공하지 않습니다.

### 실제로 확인한 제약

1. **브라우저에서 원본 API를 직접 읽기 어렵습니다.**
   `GET /top_scores/1667`에 `Origin: https://testrapod.github.io`를 보내 HTTP 200을 확인했지만,
   응답에는 `Access-Control-Allow-Origin`이 없었습니다.
   [CORS 규칙](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)에 따르면 이 상태에서는 다른 출처의 웹 페이지가 `fetch()` 응답을 읽을 수 없습니다.
   헤더와 표준에 근거한 판단이며, 실제 배포 사이트에서 브라우저 테스트를 수행한 것은 아닙니다.

2. **오래된 회차를 원본 API에서 다시 가져올 수 없습니다.**
   1회차 요청의 실제 응답은 다음과 같습니다.

   ```json
   {"detail":{"type":"InvalidAnswerId","description":"이 날의 가장 유사한 단어는 현재 사용할 수 없습니다. 그저께부터 내일까지만 확인할 수 있습니다."}}
   ```

   앞으로 수집한 회차는 JSON으로 보관하면 계속 제공할 수 있습니다.
   이미 기간이 지난 회차는 별도 보관 데이터가 없다면 이 API만으로 복원할 수 없습니다.

3. **품사 분석은 생성 단계로 옮겨야 합니다.**
   [KoNLPy는 Java 의존성이 있는 분석기](https://konlpy.org/en/latest/install/)입니다.
   Actions에서 기존 Okt를 실행하고 품사를 JSON에 포함하면 현재 동작을 유지할 수 있습니다.
   단순히 JavaScript에서 단어 끝 글자로 품사를 추정하면 결과가 달라질 수 있습니다.

### 제안 구조

```mermaid
flowchart LR
    API[꼬맨틀 API] --> JOB[GitHub Actions: Python + Java]
    JOB --> DATA[회차별 JSON 저장 · 품사 사전 계산]
    DATA --> PAGES[GitHub Pages: HTML/CSS/JavaScript]
    PAGES --> USER[브라우저: 회차 · 순위 선택과 힌트 보기]
```

- `data/1667.json`처럼 회차별 파일과 조회 가능한 회차 목록을 저장합니다.
- 최초에는 현재 조회 가능한 지난 회차부터 오늘까지 수집하고, 이후 오늘 회차를 매일 추가합니다.
- 날짜는 한국 시간 기준으로 계산하고, 아직 공개되지 않은 미래 회차는 배포하지 않습니다.
- 방문자는 같은 사이트의 JSON을 읽으므로 원본 API의 CORS 제약을 피할 수 있습니다.
- 초성, 글자 수, 한 글자 공개는 JavaScript로 쉽게 구현할 수 있고, 품사와 유사도는 JSON을 사용합니다.
- 초기 화면은 정답을 숨기고, 힌트별 버튼으로 원하는 정보만 공개하도록 구성할 수 있습니다.
- 모바일 대응과 회차·순위 입력 검증을 포함하되, 현재 규모에는 순수 HTML/CSS/JavaScript로 충분합니다.
- 프로젝트 사이트의 `/komantle-helper/` 경로를 고려해 JSON 등 자원 경로를 상대 경로로 작성합니다.

### 운영 시 고려할 점

- 매일 한국 시간 00:07 무렵 데이터를 갱신하고 실패 시 기존 파일을 유지하는 구성을 권장합니다.
  [Actions 예약 실행은 지연/누락될 수 있고 공개 저장소의 60일 비활성 시 자동 비활성화됩니다.](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)
  수동 재실행과 재시도, 데이터 기준일 표시가 필요합니다. 정확히 자정에 반영되는 방식은 아닙니다.
- 회차 JSON을 매일 배포할 때 이전 회차 파일도 유지해야 합니다. 새 빌드가 오늘 파일만 포함하면 과거 기록이 사라집니다.
- 정답을 화면에서 숨겨도 배포된 JSON에는 포함됩니다. 클라이언트에서 공개 여부를 조절하는 힌트 도구의 특성입니다.
- 수집 데이터 공개 전 원본 서비스의 이용 조건과 재배포 가능 범위를 확인해야 합니다.

실시간으로 임의의 회차를 서버에서 조회해야 한다면 별도 API 서버나 서버리스 함수가 필요합니다.
현재처럼 하루에 한 번 바뀌는 힌트 도구라면 위의 사전 생성 방식이 더 단순합니다.
